# Prepare the GitHub repository

Suggested repository name: **variant-reconciliation-system**

Suggested description:

> A creative workflow tool for reconciling source variants, recording content decisions and preparing a checked production handoff. Public demo and case study by Laura Mujica.

Suggested topics: `creative-workflows`, `automation`, `content-systems`, `javascript`, `editorial`, `ai-assisted-development`, `case-study`.

## Upload the project

Create an empty repository in the intended GitHub account. Upload the **contents** of the extracted `variant-reconciliation-system` folder so `README.md`, `demo/`, `docs/` and `package.json` appear at repository root.

The README contains the project introduction and links to the case study and demo files. An HTML link viewed within GitHub displays the source file; it becomes an interactive page only when served by a web host.

## Optional interactive demo with GitHub Pages

Once the repository is ready and the demo has been reviewed, GitHub Pages can serve this static project. Select the `main` branch and repository root as the publishing source. The root HTML forwards to the `demo/` folder. No build step or backend is required.

The public demo stores each visitor’s review locally. It does not connect to the original client project or share visitor decisions.
